# 喝了么 v0.3.0

个人鸡尾酒工具。纯 HTML / CSS / JavaScript，继续使用 GitHub Pages；没有构建依赖、付费数据库或服务器。

## 这次新增

- 当前 IBA 官网的 102 份配方：中英文名称、用量、中文步骤、杯形、装饰和独立来源链接。核对日期：2026-09-21。
- 筛选保留风味标签（可多选）与来源（单选），以及收藏、材料可用性；移除饮用形态、类别派系和基酒筛选。
- 每份配方有一个来源词条和独立的来源链接 / 备注。IBA 三个系列分别记为「IBA · 难忘经典」「IBA · 当代经典」「IBA · 新时代」。
- 调酒材料与装饰分开；装饰可以为空，不影响“现在能做”。可选材料和明确的替代材料单独处理。
- 杯形、风味标签和来源可点选，也能在编辑时添加选项。
- 同一配方可保存多个命名比例，附记录者、材料、装饰、步骤与笔记。
- 本体与变体关联；删除本体不会删除其变体。
- 酒柜默认只读，点击“修改酒柜”后才可勾选；保存才落盘并同步，取消不改库存。
- 酒柜按分组 → 类别 → 子类浏览具体酒款，可直接搜索品牌；可以在当前类别下新增子类或产品。
- 酒谱在任意一级选择材料；选类别就显示类别，指定产品就显示产品；每行可记录多个替代品。

## 材料与品牌

| 酒柜记录 | 配方要求 | 满足 |
|---|---|---|
| 杜林 Rouge / 马天尼 Rosso | 甜红味美思 | 是 |
| 未指定品牌的甜红味美思 | 仙山露 Cinzano Rosso | 否 |
| 君度 | Triple Sec | 是 |
| 波士蓝橙 | 君度 | 否 |
| 安高天娜芳香苦精 | 佩肖氏苦精 | 否 |

材料目录允许任意深度，不要求每条记录凑齐三级。品牌是产品属性；金酒、苏格兰威士忌是类别，拉弗格 10 年是具体产品。产品可以不填上级分类，品牌属性也可留空，产品名称和固定 ID 仍可用于精确匹配。分类路径可在详情中展开，不占据材料名称。

产品可满足祖先品类，但不会反向推断品牌，也不会默认互换同类产品。`matchParent=false` 是匹配边界：黑刺李金酒可从金酒目录浏览，但不能自动满足普通金酒配方；猴王 47 干金酒和黑刺李产品分开记录。Cocchi Americano 与其 Storico 红味美思分别建档，不按同品牌等同。

配方确实允许替代时，在材料行展开“允许替代材料”逐一选择，可以添加多个；用量沿用该行，仅对当前配方 / 比例版本生效。详情会区分“酒柜拥有原材料”和“使用替代品”。若整套用量或步骤变化，另建比例版本。IBA 原文只指定 Triple Sec 的配方仍保留子类，不擅自改为君度。

新录入的酒类应选具体产品；青柠汁、糖等通用材料可以直接勾选。旧库存类别保留在“待补充具体酒款”，不会猜测品牌，也不会自动删除；确认实际产品后再取消旧记录。类别和产品的新增、修改都属于编辑草稿，只有保存酒柜 / 配方后才持久化并同步，取消会一并撤销。

## 升级现有 GitHub Pages

1. 先在旧站“同步与数据”导出 JSON 备份。
2. 将压缩包内文件按原目录合并到 `Vio1331/mixbook` 根目录，更新网页脚本、样式和 `assets/`。不要只上传 ZIP 本身，不要上传私人数据备份或 Token。
3. Pages 保持 `main` 分支、根目录；`.nojekyll` 确保按静态文件发布。
4. 部署后关闭旧网页和主屏幕窗口，再重新打开。不要通过清除网站数据来刷新缓存，否则可能删除未同步的记录。

首次从 v1 / v2 升级到 v3 时，先保存 `backup-before-v3` 本机快照，再迁移 IndexedDB 数据；库存、收藏、个人配方、比例和笔记保留。未改动的初版重复示例替换为 IBA 条目，非 IBA 示例保留。删除的目录配方不会在每次刷新时恢复。材料名称升级仅更改尚未自定义且仍等于旧默认值的记录，并将旧名称保留为别名；固定材料 ID 不变。

数据版本为 v3，旧版网页会拒绝读取，防止丢失新的匹配边界。同一数据仓库的各设备应关闭旧窗口、更新网页后再同步。一台设备建议只用一个编辑标签页。

## 免费数据同步

网页文件放公开仓库；个人配方、库存、比例、选项和收藏保存在 IndexedDB，可选同步到独立的私有 GitHub 仓库。

首次配置：创建私有仓库（如 `mixbook-data`），添加 README 初始化默认分支。为网页创建仅允许这个数据仓库的 Fine-grained Token，授予 **Contents: Read and write**，再填入网页“同步与数据”。默认文件名 `mixbook.json`。不要将 Token 发到聊天里。

令牌默认仅存当前浏览器会话；勾选“在此设备记住”后存于浏览器本地存储，不是系统钥匙串。令牌不进入导出文件、网页源码或数据仓库。

- “前台自动同步”由独立开关控制，更改开关后必须点击“保存同步设置”才会生效；开启后，保存数据、回到前台和前台每 60 秒尝试合并同步，关闭并保存后不再自动同步。手动同步时必须明确选择“上传本机到仓库”或“从仓库下载到本机”，不会在方向不明时覆盖数据；操作前仍建议先导出备份。
- 酒柜草稿或配方表单打开时暂停同步。
- 不同记录可合并；同一配方的双端修改会提示冲突。比例属于所在配方，同一配方的并发编辑按整条配方处理。
- 写入携带 SHA，云端刚被其他设备更改时拒绝覆盖，本机修改仍保留。
- 首次连接和首次创建文件需确认，只接受私有数据仓库。
- 导入与云端 JSON 上限均为 1 MiB；图片作为静态资源，不嵌入 JSON。
- 不计算材料余量，不自动扣减用量。
- PWA 可添加到主屏幕。首次访问需联网，离线使用已缓存页面与本机数据；图片只缓存访问过的资源。

让助手更新网页仓库的 GitHub 应用授权，和网页同步私人数据的 Token，是不同的两件事。前者只需在应用授权中添加 `mixbook`，无需将私人数据仓库授权给助手。

## 本地运行

```bash
python3 -m http.server 8000
```

访问 `http://localhost:8000`。部署网址、本地服务和直接打开文件属于不同来源，本机数据不会自动互通；通过同步或导入导出迁移。

| 文件 | 职责 |
|---|---|
| `index.html` / `styles.css` | 页面入口与桌面、手机布局 |
| `app.js` | 编辑界面、库存草稿、存储、GitHub 同步 |
| `materials.js` | 酒柜与配方共用的分级材料浏览器 |
| `core.js` | 校验、材料层级、迁移、匹配与合并 |
| `seed.js` | 102 条目录与 197 条材料定义 |
| `data/recipes.tsv` / `data/ingredients.tsv` | 可维护源数据，竖线分隔 |
| `data/material-catalog.json` | 酒款官方来源、别名、匹配边界与保守迁移规则 |
| `data/sources.json` / `data/categories.json` | 官方来源与分类索引 |
| `scripts/build-catalog.py` | 重建目录，无需联网 |
| `assets/cocktails/` | 已有 WebP；尼格罗尼沿用 `assets/negroni.webp` |
| `sw.js` / `manifest.webmanifest` | 离线缓存与主屏幕应用 |
| `tests/` | 核心、启动、浏览器及模拟同步验证 |

运行不依赖第三方前端库、在线字体或统计脚本。开发测试依赖只在测试环境安装，不上传 Pages。

## 来源与边界

[IBA 官方目录](https://iba-world.com/cocktails/all-cocktails/)三个分类各有 34 条。用量保留官网单位，中文步骤重新表述；未复制官方照片。三个系列作为普通来源词条；风味标签为本站的口味描述。

官网有单位缺失或不同于常见版本的条目，相关配方已注明，例如 IBA Tiki、Monkey Gland、Bee’s Knees。自己的做法可另存比例或变体。
