# 喝了么 v2.1 整站检查与优化记录

检查范围：酒谱卡片与列表、收藏、个人版本、详情与调制、酒柜、原料目录与选择器、配方编辑、草稿、导入导出、GitHub 同步、离线缓存，以及桌面和手机上的浅色与深色界面。

保留纯 HTML/CSS/JavaScript 架构、暖白与朱红的原有视觉、稳定 ID、IndexedDB 数据库和 schemaVersion 4。没有修改内置配方内容，也没有迁移用户数据格式。

## 已完成的逐项优化

| 维度 | 问题或改进点 | 实际修改 |
| --- | --- | --- |
| 页面结构 | 酒柜和酒谱的联系不够直接 | 新增原料齐全、只差一种和整理酒柜的快捷入口 |
| 页面呈现 | 筛选条件只能看，无法就地清除 | 活跃条件变为可单独移除的按钮，包含关键词、基酒、风味、来源和原料状态 |
| 展示逻辑 | 收藏后顶部数量滞后 | 收藏操作即时更新集合数量 |
| 展示逻辑 | 搜索无结果误报空收藏或没有私人配方 | 分别判断集合为空和当前条件无结果，并提供对应恢复入口 |
| 展示逻辑 | 重置筛选会丢失当前集合 | 清除条件时保留“我的收藏 / 我的配方”范围 |
| 展示逻辑 | 原料目录空结果仍引导添加库存 | 目录与酒柜使用各自对应的新增动作；支持清除分类和关键词 |
| 移动布局 | 展开筛选把结果和关闭入口推到页面下方 | 改为原生 dialog 底部面板，标题与结果按钮固定在滚动区域边缘 |
| 移动交互 | 面板打开后改变屏幕宽度会遗留隐藏内容 | 切回桌面自动关闭面板，清理副本并恢复侧栏 |
| 视觉细节 | 操作反馈不够统一 | 完善卡片焦点、筛选标签、输入行反馈、触控尺寸和克制的图片悬停动效 |
| 可访问性 | 整块重绘让键盘焦点丢失 | 收藏、筛选和调制更新后恢复对应控件焦点；详情保留滚动位置 |
| 可访问性 | 校验错误只有视觉提示 | 为错误控件增加 aria-invalid 和关联错误说明，并定位首个错误 |
| 可访问性 | 搜索需要反复定位 | 非输入及非弹窗状态下按 `/` 聚焦当前搜索框 |
| 输入逻辑 | 全角数字、半份和带分数处理不一致 | 统一规范化和解析，支持 ３０、1 / 2、1 1/2、½、半、.5 与范围 |
| 输入校验 | 零分母、倒序范围和畸形数值能绕过检查 | 拒绝零值、零分母、负数、倒序范围、无效数字格式；文本“适量”保持可用 |
| 批量录入 | 中文笔记中无空格、全角用量容易粘贴失败 | 支持“金酒３０ml”和带分数；保留不能识别或无效的原始行供修正 |
| 保存逻辑 | 异步保存期间再次提交可能重复写入 | 配方表单增加提交锁并在结束时释放 |
| 并发一致性 | 弹出确认后另一页面可能再次改动同一记录 | 配方和酒柜在真正写入事务内再次核对记录 |
| 导入一致性 | 导入确认期间的其他页面改动可能被覆盖 | 以导入快照核对实际写入状态，变化时要求重新合并 |
| 搜索稳定性 | 延迟搜索可能在切换页面后继续渲染 | 切页和重绘时取消定时器；结果渲染检查当前页面 |
| 数据结构与性能 | 递归匹配反复创建目录 Map 和遍历酒柜 | 单次操作内共用目录、路径、匹配和分类索引，操作结束后释放 |
| 派生数据 | 可制作统计与排序重复计算 | 同一数据快照共用批量分析结果，新快照重新计算 |
| 数据新鲜度 | 长期缓存可能与可变编辑草稿不一致 | 核心索引只在一次同步操作内生效，并测试原地修改后的结果 |
| 偏好恢复 | 损坏的本地 JSON 类型可能阻断原料选择 | 校验近期原料数组和同步配置字段类型，异常时使用默认值 |
| 图片加载 | 详情大图被延迟加载，可能暂时空白 | 详情使用 eager/high，列表继续 lazy，图片采用异步解码与固定尺寸 |
| 初始加载 | 启动失败时一直显示加载文字 | 添加轻量骨架、8 秒后的说明和重新加载按钮 |
| 网络反馈 | 离线后仍显示普通已保存状态 | 离线事件更新本地保存状态 |
| 离线代码一致性 | 单个脚本网络优先可能混用版本 | 代码外壳按版本完整缓存，安装完成后才提供更新入口 |
| 内容维护 | 代码缓存不能阻断 catalog.js 的独立维护 | 目录联网刷新，网络失败时使用缓存；只改内容不需要升级缓存编号 |
| 缓存容量 | 图片缓存无界增长；写入失败可能隐藏成功响应 | 图片按需缓存，上限 120；缓存失败仍显示已下载图片 |
| 缓存隔离 | 同源不同路径的网站可能互相清缓存 | 缓存命名包含 Service Worker scope，只清理本作用域旧版 |
| 更新交互 | 新版激活可能打断编辑 | 就绪后提示手动更新，编辑或同步中不激活，等待写入队列结束 |
| 存储异常 | 数据库占用或连接升级缺少明确反馈 | 处理 blocked/versionchange，关闭失效连接并提示；不清空原有存储 |
| 维护工具 | 目录审计仍依赖已删除的 seed.js 和 cocktail-system.js | 改为读取 catalog.js，调用当前校验并检查导航引用和配图 |

## 验证

- Node 回归覆盖核心校验、迁移、合并、材料匹配、目录、图标、启动降级和 Service Worker。
- 浏览器测试扩展至 18 个场景，包括 320、390、768、1440 px 布局、深色表单、旧备份导入、草稿、收藏、配方版本、撤销、跨页冲突、离线保存与模拟同步。
- 新增针对筛选面板、输入规范化、损坏偏好、延迟搜索、收藏统计、焦点恢复的回归。
- 缓存测试覆盖配额失败、离线外壳、目录更新、作用域隔离和明确激活。
- 目录审计：14 个一级菜单、79 个二级菜单、61 个内置标签、237 项原料、102 份配方；结构、引用和配图均有效。
- Chromium 同一环境微基准：102 份配方、模拟 40 条库存、连续 3 次搜索，优化前约 2913 ms，优化后约 14 ms。这只衡量搜索与匹配计算，不代表页面加载、网络或所有设备的性能。

## v2.4 原料模型与操作验收

这次将原料要求、品牌产品和实际拥有记录分开。原料不限定品牌；产品填写名称、品牌及所属原料；酒柜只保存对应身份与个人备注。名称不再兼任隐式身份选择，“特征”不再兼任任意匹配开关。

| 板块 / 组件 | 检查内容与结果 |
| --- | --- |
| 原料角色 | 无品牌的鲜果、果汁归为原料；品牌产品独立呈现；导航分组不混入选择结果 |
| 名称、品牌、别名 | 名称标识定义，品牌描述产品，别名用于搜索；同名同品牌提示复用，返回列表保留输入 |
| 搜索列表 | 原料 / 品牌产品筛选；直接命中优先、关联结果展开；最近使用、分类、空结果和更多结果可用 |
| 键盘操作 | 上下键和 Enter 选料；输入法确认不误选；重复定义的“使用已有”支持键盘提交 |
| 新增表单 | 原料只需名称与分类；产品需名称、品牌与明确原料；角色切换保留字段；错误可修正后继续 |
| 连续加入酒柜 | 成功后留在列表，已有项不可重复添加；通用原料与品牌产品按实际 ID 分别识别 |
| 酒柜编辑 | 品牌只读；备注名、笔记不改变身份；可用原料由系统计算；保留原有删除确认与撤销 |
| 原料编辑 | 新增、修改名称 / 品牌、关闭后继续、被引用时阻止删除、移出酒柜后删除均模拟通过 |
| 旧记录 | 迁移前保留备份；一次性解析旧名称；历史多个匹配与附加标签在普通编辑后保留，主动清理才删除 |
| 配方编辑 | 选料后定位用量；取消选料不产生空行；多行粘贴、用量验证、替代项、复制、排序与个人版本回归通过 |
| 配方展示 | 搜索、分页、收藏、缺料筛选、杯数换算、复制清单、调制步骤、焦点与滚动保持回归通过 |
| 目录展示 | 列表使用分隔线；名称与品牌 / 所属原料分层；手机也保留品牌，避免同名产品无法区分 |
| 同步与数据 | 模拟合并、覆盖确认、409 失败、导入导出、多页面冲突、临时存储与离线保存回归通过 |
| 视觉与响应式 | 截图复查桌面搜索、新增产品、酒柜编辑，以及手机搜索、新增、目录与深色表单；320–1440 px 布局检查通过 |

实际模拟中修复的问题：原料编辑表单的隐藏 `id` 字段遮蔽表单 ID，导致提交刷新首页；返回新增列表丢字段；重复定义提示中按 Enter 访问不存在的结果列表；手机目录隐藏品牌；旧版多个匹配在普通保存时被缩减。

验证记录：最终 30 项 Chromium 浏览器场景通过；6 个 Node 测试文件通过，补充果汁产品的方向性匹配、同品牌产品不可互换、备注不影响身份、迁移幂等与旧多项匹配保留。237 项原料、102 份配方的目录引用与配图审计通过。

范围说明：浏览器验证使用 Chromium 与模拟的 GitHub API；手机检查为响应式视口，未声称完成真实 iOS / Android 设备验证。测试数据没有写入用户真实私有数据仓库。发布缓存版本为 v2.4.0。
