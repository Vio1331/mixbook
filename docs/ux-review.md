# 全站交互审查与固定规则（v2.5）

## 产品边界

网站服务三个任务：查找并制作配方、记录自己的原料、保存与备份记录。界面元素必须帮助用户完成其中一个任务，或防止具体的数据损失。宣传语、推荐口号、重复的统计、不能直接操作的成就提示不保留。

这是后续改动的约束，不是下一轮增加推荐模块的起点。

## 先复现，再修改

在修改前以空浏览器访问，依次检查酒谱、空酒柜、添加、原料编辑、原料库、配方编辑、详情、设置，提取可见文字并截图。发现并实际复现：

- 打开“添加已有原料”，点选金酒，再关闭窗口，酒柜已经写入 1 条。关闭没有取消。
- 在原料笔记里输入“取消这次输入”，关闭，再打开，文字仍被恢复。
- 默认材料列表按拥有、最近使用、配方引用次数排序，材料顺序会随着操作变化，类别彼此穿插。
- 空酒柜显示多个零数量分类、重复的添加入口、重复数量与宣传语。
- 设置页同时显示数据总数、连接徽标、连接摘要、保存状态、未同步说明等，基本任务只是导入、导出和连接。

用户举出的“今晚调一杯”等部分旧文案不在 v2.4 本机代码中。GitHub Pages 记录显示 v2.4 部署成功，但旧 Service Worker 的等待激活机制可能让页面继续使用缓存版本。此次同时验证版本升级，不能用“代码已经改了”代替交付检查。公开页面抓取工具无法直接读取站点，因此不声称在用户浏览器复现了具体缓存状态。

## 必须一致的行为

1. 保存 / 添加是提交点。点选、输入和切换分类只修改当前表单。
2. 取消、关闭和 Escape 丢弃当前未提交操作；重新打开从已保存数据开始，不恢复或询问草稿。
3. 新建原料如果属于尚未保存的配方或尚未确认的酒柜选择，随父表单取消，不留下孤立记录。
4. “返回列表”保留当前子表单输入；子表单“取消”丢弃这次新建。两个动作分别实现，不混用名称。
5. 删除已保存记录、覆盖完整数据、处理真实写入冲突仍有确认，不能和取消输入混为一谈。
6. 分类顺序和同类材料顺序稳定；拥有状态、点击历史和配方引用次数不改变浏览顺序。搜索仍优先精确名称与别名命中。
7. 一项信息只在能帮助当前决定的位置出现。分类已由分组标题表达时，行内不重复；空酒柜不展示无内容的筛选。

## 逐项取舍

| 页面 / 元素 | 决定 | 理由与最终行为 |
| --- | --- | --- |
| 顶部品牌副标题 | 删除 | 不参与查配方或录入 |
| 顶部保存 / 同步状态 | 保留 | 告知是否已保存、是否待同步，属于操作反馈 |
| 全站页脚宣传与技术状态 | 删除 | 与品牌、顶部状态重复；版本号移至设置 |
| 首页推荐条、随机一杯、随机排序 | 删除 | 不服务明确查找任务，不能占据默认浏览入口 |
| 主页酒柜数量、原料齐全快捷入口 | 删除重复入口 | 可制作性由筛选区提供，酒柜仍有明确跳转 |
| 全部 / 我的配方 / 收藏 | 保留 | 切换不同内容集合，收藏数量能反映刚执行的操作 |
| 配方名称、英文名、照片 | 保留 | 用于识别与搜索；照片按需加载，失败有占位图 |
| 每张卡片“经典配方” | 删除 | 默认目录里重复同一事实；仅标记个人配方 / 个人版本 |
| 空酒柜时每张卡片“缺 N 种” | 删除 | 尚未记录原料，连续缺料提示没有判断价值 |
| 已录入酒柜后的缺料状态 | 保留 | 能支持选酒；详情保留逐行匹配依据 |
| 基酒、风味、来源、缺料筛选 | 保留 | 都改变查找结果；风味说明明确“任一”匹配语义 |
| 卡片 / 列表、排序、分页 | 保留 | 支持不同浏览密度和大目录；移除随机排序 |
| 酒柜添加按钮 | 改为“添加原料” | 页面已说明酒柜上下文，不再要求理解“已有原料” |
| 空酒柜分类、搜索与重复添加按钮 | 删除 | 没有记录可筛选；只保留主操作与简短空状态 |
| 酒柜“更多可能”与补料推荐 | 删除 | 与记录任务无关；不在保存后附带推荐话术 |
| 酒柜材料行“用于 N 份配方” | 删除 | 该行打开编辑而非那些配方，数字不能支持当前操作 |
| 我的原料 / 原料库 | 保留并改名 | 区分拥有记录与可选定义；不把原料库总数放入页签 |
| 酒柜、原料库列表 | 按类别分组 | 不再按添加顺序或使用次数让酒与果汁交错 |
| 行内分类与“不限定品牌” | 去重 | 分组标题已表达类别；行内只保留必要品牌或更具体类型 |
| 添加窗口默认列表 | 改为分类入口 | 空搜索不再倾倒常用材料；可直接搜索或选择类别 |
| 材料搜索 | 保留明确分组 | 名称 / 别名命中优先；水果与果汁分开，关联结果按需展开 |
| 原料 / 品牌产品切换 | 删除 | 录入前不要求用户先学习数据模型 |
| 新建表单 | 名称、类型、品牌选填 | 单一表单；别名展开后填写，类型可搜索；品牌产品不能归到另一产品 |
| 点选加入酒柜 | 改为待确认多选 | 选中不落库；最后一次提交“添加 N 项” |
| 已选材料核对 | 保留名称与移除按钮 | 跨类别选择后仍能检查内容；不是只有一个无法核对的数量 |
| 取消新建或整个添加 | 丢弃对应操作 | 不恢复旧表单，不落下自建材料；不出现草稿术语 |
| 酒柜品牌 | 只读 | 来自原料定义，避免两个地方维护同一产品品牌 |
| 备注名称、笔记 | 保留为可选 | 记录个人称呼、开封和口感，不改变配方匹配身份 |
| 可替代关系 | 按需展开，只读 | 解释匹配结果，不让描述性口感成为匹配开关 |
| 历史额外匹配 | 保留并可主动清理 | 普通编辑不静默删除旧信息 |
| 配方编辑默认内容 | 名称、原料、做法 | 英文名、记录者、杯型、调制方式、来源等移入更多信息 |
| 配方名称标题与字段名、做法与步骤双标题 | 去重 | 一个字段只需要一个清楚的标签 |
| 多行粘贴、替代项、可选原料、排序、复制行 | 保留 | 对实际录入有用；低频行操作折叠，取消选料不创建空行 |
| 配方版本 | 保留，入口改为“调整配方” | 表达实际动作；保留原配方，并记录个人修改 |
| “复制配方”和“创建变体”并列入口 | 合并默认入口 | 保留复制；关联原配方仍可在更多信息中设置，已有变体继续显示 |
| 详情杯数、复制清单、调制步骤 | 保留 | 直接支持实际制作；换算、键盘焦点、步骤勾选回归验证 |
| 设置页数据统计与重复连接状态 | 删除 | 备份和同步不需要先阅读统计面板 |
| 设置页 | 备份 / 跨设备同步 | 导入导出直接可见；连接说明、覆盖数据与清空操作折叠 |
| 同步表单分支和路径 | 折叠 | 默认配置足够，保留高级修改能力 |
| 同步成功强制等待 | 删除 | 完成后恢复操作，用短消息反馈结果 |
| 图片悬停缩放、卡片浮起、提示位移 | 删除 | 不表达必要状态；保留颜色反馈、加载指示和减少动画支持 |
| 更新机制 | 缓存完整后激活 | 不再长期等待手动激活；不强制刷新编辑中的页面，下次导航加载完整新版 |

## 验证方法

浏览器用例覆盖：关闭、Escape、返回、取消子表单、重新打开、批量添加、取消选择、重复创建、编辑、删除、撤销、配方输入与保存、旧记录迁移、跨页面冲突、导入导出、离线、模拟 GitHub 同步，以及旧缓存向新缓存升级。

专门验证旧缓存升级时：打开未保存的原料笔记，安装新 Service Worker，确认输入未被打断；取消后刷新，确认新版脚本加载，已保存酒柜仍在，取消的笔记未写入。

截图检查桌面和手机的首页、空酒柜、分类入口、搜索、选择、原料编辑、原料库、新建、配方编辑、详情与设置；手机检查浅 / 深色，并进行 320–1440 px 溢出回归。模拟 GitHub API，不写入用户私有数据仓库；响应式视口不等同于真实 iOS / Android 设备测试。


## v2.6 原料身份与分类复核

- 复现：自建青柠汁和目录青柠汁同名同父级但 ID 不同，显式库存只认前者，酒谱只认后者。修复引用，而不是只过滤重复显示。
- 归并条件包含父级、品牌、匹配边界、特征与图片，保留用户输入的别名；鲜果、果汁、果泥及不同朗姆类型不因名称相近而合并。
- 逐项检查库存、正文、装饰、替代材料、比例版本、产品父级及特征引用。旧备份导入与数据合并后再次归并，防止同一冲突重新出现。
- 朗姆等分类不再混排基础类型、产地品种、品牌产品。基础选项直接可选，细分可展开，精确搜索直达；选中一项后不折叠列表。
- 回归：升级后搜索只出现一个青柠汁；已有库存正确标记；库存改名不改变身份，删除后显示缺料，再添加恢复匹配；导入旧备份不产生重复；桌面与手机检查无横向溢出。
- 用户提供的实际备份仅用于隔离环境核验，不进入代码库。验证库存记录、配方、笔记、比例版本、收藏均保留。


## v2.7 统一目录与多条酒柜记录（历史记录，录入交互已由 v2.8 替换）

- 删除以“已拥有原料 ID”阻止再次添加的限制。目录与库存不是同一层数据：原料定义唯一，库存记录可以多条；批量勾选的选中状态只作用于本次操作。
- 移除只按内置标记划分的“产地与细分类型 / 品牌产品”区块。所有酒类、果汁与食品使用相同关系树，从父级展开下级；搜索保留所属路径。原料和品牌产品都能选择，父类别不会被误当成全部下级。
- 新建和编辑共用同一目录。浏览目录时聚焦当前类别，可返回全部分类；展开下级自动滚动到新内容。中文类型名称保留原外文名称为别名。
- 补充分类可以选择自建类型，与内置类型使用相同规则。创建测试产区，再创建属于黑朗姆且补充该产区的产品，验证可在两条目录路径找到，匹配两个分类。
- 科学归属检查覆盖葡萄酒、利口酒、伏特加、朗姆、饮品等，不止用户举出的两个分类。保留稳定 ID 与自定义内容，修复未编辑的内置父级。
- 实测：已有银龙舌兰再次添加；新建唐胡里奥银牌并选择真实类型；同款产品再次添加；独立改名、删除后其余库存仍可满足配方；资料库“再添加”；全部类别在手机端展开，无横向溢出且每项可选原料均可到达。
- 原备份隔离升级核验：39 条库存、110 份酒谱，笔记、比例版本、图片、收藏和库存 ID 保留；取消新建不写入记录。私人数据不加入代码库。
- v2.7 升级前另外保存 `backup-before-v2.7-hierarchy` 本机快照，无恢复草稿弹窗。最终 38 项浏览器回归通过；最后的按钮点击区域与多级匹配另行复核。

## v2.8 名称、分类、品牌直接编辑

库存不再以勾选分类或产品完成添加。添加和编辑都使用三个直接可编辑字段：名称、分类、品牌。选择分类返回表单，保存才写入；关闭即取消。删除备注名称、原品牌备注、旧记录补充信息、选中标签和重复返回按钮。

分类树排除具体品牌产品，同级文字对齐；分支展开、叶子选中、加号选择父级。自建分类和添加一瓶酒使用各自明确的入口。来源与库存条件使用标签筛选；设置页仅连接说明折叠，数据操作直接显示，三种同步同级，版本固定底部。

操作、真实备份核对、截图审查及测试证据见 [v2.8 发布检查记录](release-2.8-review.md)。此记录取代历史版本中与新交互矛盾的验收描述。
