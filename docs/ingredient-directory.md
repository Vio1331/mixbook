# 全站内置材料目录

> 内置目录以 `catalog.js` 为唯一维护入口；既有 ID 和配方引用保持稳定。

## 信息模型（v2.8）

酒柜记录直接包含名称、分类、品牌。名称是酒或原料本身的名称，品牌是可编辑输入，不是备注。每条记录拥有独立 ID；保存一瓶不会改动其他瓶。

- 添加与编辑使用同一个三字段表单，选择分类只填写表单，点击保存才写入。取消、关闭、Escape 均不恢复草稿。
- 分类选择器和分类管理页只展示非品牌类型。乐加维林 16 年等具体产品不能出现在分类树里；配方选择器仍可单独搜索和选择这些具体产品。
- 分支行点击展开，叶子行点击选择，父级加号选择该父级；同级文字预留相同的箭头位置，保持对齐。没有批量选中标签、返回分类的重复按钮或含义不清的“新建”入口。
- 旧酒柜中的名称和品牌直接回填。旧笔记、图片和未修改的关联关系保留在备份数据中，不再以“旧记录补充信息”等只读界面阻碍编辑。
- 保存品牌原料时复用或创建具体产品定义，归属于用户选择的分类。编辑独立记录不修改其他记录共用的定义。已知品牌产品仍可满足指定产品酒谱；没有品牌的类别不能冒充具体产品。
- 分类定义与产品引用继续使用稳定 ID；同名修复、上下级匹配和配方明确替代项保持原有边界。实际库存不足不会因展示改动变成原料齐全。

### 同名原料与旧数据修复

- 库存和酒谱必须引用同一个原料 ID；两个名称相同的独立定义不会天然互相匹配。安装目录、导入、保存与同步流程统一修复已确认的重复定义。
- 仅当自建条目的名称命中内置名称或明确别名，且所属原料、匹配边界、特征相同，并且双方无品牌、没有图片冲突时才归并。多义名称不猜测，品牌和不同加工形态不互换。
- 保留原料别名和图片，并迁移正文、装饰、替代项、比例版本、产品父级、标签及库存引用。库存记录不合并，备注名、笔记与记录 ID 保留。旧备份再次导入不会复活重复定义。
- 青柠与鲜青柠、柠檬与鲜柠檬、西柚汁与葡萄柚汁采用统一定义。橙汁统一以“橙汁”展示，保留“鲜橙汁”等搜索别名；鲜榨建议由具体配方表达，果汁与果泥仍是不同原料。
- 升级前本机数据保存在 IndexedDB 的 `backup-before-material-dedup`。原料归并不引入任何草稿提示。
- 所有分类统一使用可展开的真实关系树，节点名称展开下级，旁边的加号选择当前类型。没有内置特征专属分组；自建条目与内置条目按同样规则出现。名称搜索显示完整路径；新建与编辑均可浏览分类目录，不要求记住类型名。

## 录入与取消

酒柜添加先选择，点击“添加 N 项”一次性提交。关闭、取消、Escape 不写入记录，也不恢复旧输入。新建原料如果尚未随酒柜或配方提交，取消父表单时一起丢弃。默认浏览按分类组织，拥有与点击历史不影响顺序；具体界面取舍见 [交互审查](ux-review.md)。


## 酒柜录入示例

添加唐胡里奥银牌：打开“添加原料” → 名称填“唐胡里奥银牌” → 分类选择“龙舌兰 / 特基拉 / 银龙舌兰” → 品牌填“唐胡里奥” → 保存。已存在另一瓶银龙舌兰时仍可添加，两条记录可分别编辑、删除。

编辑拉弗格 10 年：名称显示“拉弗格 10 年”，品牌显示原有“Laphroaig”，分类显示“威士忌 / 苏格兰威士忌 / 艾雷岛单一麦芽威士忌”。三项均可直接修改，不需要理解“备注名称”“原品牌备注”等概念。
